# Network Intelligence

Сервис для **анализа и мониторинга доменов и IP**: проверка DNS, HTTP, геолокации IP, TLS-сертификата и открытых портов — как по команде, так и в автоматическом режиме с уведомлениями об изменениях.

---

## Зачем это нужно

Один инструмент, который отвечает на вопросы о любом сайте или сервере:

- 🔎 **Что это за сайт?** — IP-адреса, DNS-записи (A/AAAA/MX/NS), HTTP-статус и заголовки, TLS-сертификат (срок действия, протокол), открытые порты.
- 🧭 **Где сервер?** — геолокация по IP (страна, город, координаты) из локальной базы.
- 📡 **Всё ли с ним в порядке?** — постоянный мониторинг: сервис сравнивает результаты соседних проверок и фиксирует изменения (ответ стал медленнее, сменился IP, упал статус, закрылся порт…).
- 🛎 **Что изменилось?** — события записываются в базу и отправляются в Telegram / MAX.

Использование: разведка перед подключением к серверу, наблюдение за своими сервисами, контроль доступности, отслеживание срока действия TLS-сертификатов.

## Что уже можно делать

### 1. Полный анализ домена

Анализаторы (`src/analyzers/`), запускаются все вместе:

- **DNS** — A (IPv4), AAAA (IPv6), MX, NS
- **HTTP** — статус, время ответа, заголовки (включая security-заголовки: HSTS, CSP, X-Frame-Options, XSS-Protection), title страницы, размер тела
- **IP / геолокация** — страна, регион, город, координаты и пр. по локальной базе ipapi.is (без внешних HTTP-запросов)
- **TLS** — протокол и сертификат (valid_from / valid_to, сколько дней осталось)
- **Порты** — проверка 21, 22, 25, 53, 80, 443, 8080

### 2. Мониторинг

- Запуск мониторинга с интервалом в минутах; каждый цикл: анализ → сохранение результата.
- Режим **`events`** сравнивает два последних результата и при изменениях (время ответа, IP, MX/NS, HTTP-статус, server, размер тела, порты; пороги заданы в `src/monitor_events.ts`) записывает **событие** в `monitor_events`.
- При старте сервиса **активные мониторы автоматически возобновляются** из базы.
- Остановка: по одному монитору, по пользователю или все сразу.

### 3. Интерфейсы

- **CLI** — `node dist/index.js scan <domain>` / `monitor <domain> <minutes>`.
- **HTTP API** (порт `3000`) — запуск скана, управление мониторами, история результатов (см. раздел «API»).
- **Telegram-бот** — `/scan`, `/monitor`, `/events`, `/stop`, `/monitors`, `/app` (открывает Mini App).
- **MAX-бот** — те же команды через мессенджер MAX (`platform-api2.max.ru`).
- **Веб-интерфейс** (Vite + React) — страницы «Сканирование» и «Мониторы».
- **Telegram Mini App** — показывает мониторы текущего пользователя Telegram.

## API

HTTP-сервер запускается в `src/api/startApiServer.ts` (порт `3000`).

| Метод и путь | Действие |
| --- | --- |
| `GET /api/scan/<target>` | Полный анализ цели, сохранение в `scans` |
| `GET /api/monitorsUser/<tgUserId>` | Мониторы пользователя |
| `GET /api/monitorsResolts/<id>` | Все результаты монитора по ID |
| `GET /api/eavents/<target>` | Запуск анализаторов + сохранение скана (тестовая страница событий) |
| `GET /api/startMonitor/<id>` | Запустить монитор |
| `GET /api/stopMonitor/<id>` | Остановить монитор |
| `GET /api/deleteMonitor/<id>` | Удалить монитор |

## Запуск

### Требования

- **Node.js 22+** (используются встроенные модули `node:dns`, `node:tls`, `node:net`, `node:http`, `fetch`)
- **MySQL** (по умолчанию `localhost:8889`, БД `network_intelligence`)
- **Гео-база** `data/ipapi/geolocationDatabaseIPv4.csv` (~209 МБ, скачивается отдельно, см. [«Гео-база»](#гео-база-ipapiis))

### Переменные окружения (`.env`)

| Переменная | Описание |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
| `TELEGRAM_CHAT_ID` | Тестовый чат Telegram |
| `MAX_BOT_TOKEN` | Токен для API платформы MAX |

### Сборка и запуск

```bash
# 1. Компиляция TypeScript → dist/
npx tsc

# 2а. Только CLI
node dist/index.js scan example.com
node dist/index.js monitor example.com 5
node dist/index.js monitor stop 1        # или: monitor stop all

# 2б. Полный сервис (API + мониторы + Telegram-бот + MAX-бот)
node dist/startAPIMonitorsBots.js
```

### Веб-интерфейс

```bash
cd web-app
npm install
npm run dev        # Vite dev-сервер
```

### Telegram Mini App

```bash
cd mini-app
npm install
npm run dev
```

## Гео-база ipapi.is

IP-геолокация работает по **локальной** базе от [ipapi.is](https://ipapi.is/) — без внешних HTTP-запросов и API-ключей.

База **в Git не хранится** (файл ~209 МБ, превышает лимит GitHub). Установка:

1. Скачайте **Geolocation Database IPv4** с https://ipapi.is/ → раздел «Databases» / «IP to Geolocation».
2. Сохраните как `data/ipapi/geolocationDatabaseIPv4.csv`.
3. При запуске в логе появится `IP database loaded: N records`.

Подробности и атрибуция: `data/ipapi/README.md`.

## Известные особенности и ограничения

- Параметры БД (`host/port/user/password/database`) захардкожены в `src/database/connection.ts`.
- В веб-интерфейсе и API используется **тестовый Telegram User ID** `503362430` вместо авторизации.
- `alert()` при событии пока только пишет в консоль.
- Порты проверяются по фиксированному списку [21, 22, 25, 53, 80, 443, 8080].
- Активные мониторы возобновляются при старте сервиса, но повторная проверка запущенных мониторов в рантайме пока не реализована.
- Mini App указывает на временный trycloudflare-туннель.
- Проект в активной разработке; API и формат данных могут меняться.
